# sh-notice-mcp

SH(서울주택도시개발공사)에 새 **입주자 모집공고**가 올라오면, Claude가 공고문 PDF를 읽고 **내 조건과 대조해 요약**합니다. 그중 **내가 확인한 일정만** 캘린더에 넣어 주는 [MCP](https://modelcontextprotocol.io) 서버입니다.

> ⚠️ **비공식 도구입니다.** SH공사와 관계가 없습니다. 자격 판단과 비용 계산은 **참고용**입니다. 신청 전에 반드시 공고문 원문과 청약 사이트에서 확인하세요. 사이트에 부담을 주지 않도록 요청 간격은 1초 이상이고, 게시판 1페이지만 확인합니다. 개인 용도로만 쓰세요.

Claude 데스크톱 앱에서 이렇게 말하면 됩니다.

- "최근 뜬 공고 있어?" → 내가 보기로 한 유형의 최근 모집공고와 접수 상태(접수 중·예정·마감)
- "고덕강일 공고 정리해 줘" → 자격(✅/⚠️/❌ + 공고문 쪽 번호), 타입별 필요 현금·대출·취득세·월 부담, 청약 전략, 내 일정
- "접수 일정 캘린더에 넣어 줘" → 화면에 확인 창이 뜨고, **내가 체크한 일정만** 등록
- "접수했어" / "당첨됐어" → 다음 단계 일정(발표 / 서류·계약)만 제안
- "접수번호는 512345야" → 저장해 두었다가, "당첨됐는지 봐줘" → 발표 명단 PDF에서 찾아 당첨 / 예비 순번 / 명단에 없음을 알려 줌 (최종 확인은 SH 시스템·ARS)
- "행복주택만 보고 싶어" → 프로필의 조회 범위를 바꿈 (확인 창을 거친 뒤 저장)

```
새 공고 감지 → 모집공고문 PDF만 골라 읽기
→ 공고가 묻는데 내 조건에 빠진 항목은 먼저 질문
→ 가격표는 서버가 직접 파싱·계산 (분양가, 대출, 취득세, 토지임대료 보증금 전환, 전세대출)
→ Claude가 정해진 형식으로 요약 (자격 / 비용표 / 대출 / 일정 / 특이점)
→ 일정마다 서버가 원문에서 근거 문장을 찾음. 못 찾으면 거부
→ 확인 창에서 내가 체크한 일정만 캘린더에 등록
```

## 무엇을 볼지: 프로필 `[watch]`

모든 조회는 SH의 [공고 및 공지 > 전체](https://www.i-sh.co.kr/main/lay2/program/S1T294C295/www/brd/m_241/list.do?multi_itm_seqs=1,2,4,8,16,32,64,128,256,512,1024) 게시판 한 곳에서 합니다. 어떤 공고를 볼지는 프로필 파일의 `[watch]` 항목으로 정합니다.

```toml
[watch]
sale = true                            # 주택분양 (적지 않으면 true)
rent = true                            # 주택임대 (적지 않으면 true)
rent_types = ["장기전세주택", "행복주택"]  # 주택임대 중 볼 공급유형. 비우면 전체
include_words = ["강동", "고덕"]         # 제목에 이 중 하나라도 있는 공고만 (선택)
exclude_words = ["잔여세대"]             # 제목에 있으면 제외 (선택)
```

`rent_types`에는 SH 검색 화면의 '공급유형' 목록 이름을 그대로 씁니다. `장기전세`, `국민임대`처럼 줄여 써도 됩니다.

> 국민공공임대주택 · 장기전세주택 · 매입임대주택 · 장기안심주택 · 희망하우징 · 행복주택 · 청년안심주택 · 전세임대 · 영구임대주택 · 재개발임대주택 · 두레주택 · 사회주택 · 도시형생활주택 · 수요자맞춤형

Claude에게 "행복주택만 볼래"라고 말해도 됩니다. 그러면 `sale = false`, `rent_types = ["행복주택"]`으로 바꾸자고 제안하고, 확인 창에서 체크한 뒤에 저장합니다. 토지분양처럼 주택이 아닌 공고는 보지 않습니다.

모집공고 필터에도 '경쟁률', '당첨자 발표' 같은 후속 글이 섞여 나옵니다. 이런 글은 제목으로 걸러 냅니다. Claude에게 "지금 어떤 공고 보고 있어?"라고 물으면 `list_boards`가 현재 설정과 쓸 수 있는 값을 보여줍니다.

비용표 자동 계산은 **분양**(토지임대부 포함)과 **장기전세** 공고문 형식을 지원합니다. 다른 임대 유형은 Claude가 공고문 표를 직접 읽어 정리합니다.

## 설치

macOS와 Python 3.10 이상이 필요합니다. 버전은 `python3 --version`으로 확인하세요. 낮으면 `brew install python`으로 설치합니다.

```bash
git clone https://github.com/<you>/sh-notice-mcp.git
cd sh-notice-mcp
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/pytest            # 네트워크 없이 도는 테스트 (약 5초)
```

macOS가 아니어도 서버는 돌아갑니다. 이때 캘린더는 `.ics` 파일로 저장되고, 확인은 MCP elicitation을 씁니다. 아래 [다른 환경](#다른-환경)을 보세요.

### 1) 내 조건 적기

처음 실행하면 `~/.sh-notice-mcp/profile.toml` 양식이 생깁니다. 무엇을 적는지는 [`profile.example.toml`](profile.example.toml)을 참고하세요. 아는 항목만 앞의 `#`을 지우고 값을 적으면 되고, 금액 단위는 만원입니다.

- **적지 않은 항목은 '모름'으로 봅니다.** 0과 다릅니다. 공고가 그 항목을 기준으로 삼으면 Claude가 먼저 묻습니다.
- Claude에게 말로 알려 줘도 됩니다. 이전 값과 새 값을 확인 창에서 보여 준 뒤, 체크한 항목만 저장합니다.
- 주민등록번호나 계좌번호 같은 식별정보는 받지 않습니다. 이 파일은 내 컴퓨터에만 있고, 서버가 외부로 보내지 않습니다. 다만 Claude가 판단하려면 대화 중에 내용을 읽습니다.

### 2) Claude 데스크톱 앱에 연결

`~/Library/Application Support/Claude/claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "sh-notice": { "command": "/절대경로/sh-notice-mcp/.venv/bin/sh-notice-mcp" }
  }
}
```

앱을 완전히 종료(Cmd+Q)했다가 다시 열고 "최근 뜬 공고 있어?"라고 물어보세요. 처음 캘린더에 쓸 때 macOS가 캘린더·자동화 권한을 묻습니다. 허용하면 **SH 공고** 캘린더가 생깁니다.

### 3) 터미널에서 확인 (선택)

```bash
.venv/bin/sh-notice-run                            # 새 공고 확인 (첫 실행은 지금 있는 글을 기준선으로만 저장)
.venv/bin/sh-notice-run --pdf rent_jeonse 309467   # 어떤 PDF를 골랐는지와 목차
.venv/bin/sh-notice-run --preview rent_jeonse 309467
.venv/bin/sh-notice-run --review rent_jeonse 309467  # 터미널에서 y/n으로 골라 등록
```

`board_id`(`sale`, `rent_all`, `rent_jeonse`, `rent_happy` …)는 `list_boards`에서 볼 수 있습니다. `seq`는 게시글 주소의 `seq=` 값입니다.

### 4) 매일 자동 확인 (선택, Anthropic API 키 필요)

새 공고 확인은 AI 없이 코드로만 합니다. 새 공고가 없으면 아무 일도 하지 않으므로 비용이 들지 않습니다. 새 공고가 있을 때만 에이전트가 Claude API로 요약하고, 결과를 알림과 파일로 남깁니다. 캘린더 등록은 이때도 확인 창을 거칩니다.

```bash
.venv/bin/pip install -e '.[agent]'
security add-generic-password -s sh-notice-anthropic -a "$USER" -w    # API 키를 키체인에 저장 (파일에 두지 않음)
.venv/bin/sh-notice-agent "최근 공고 정리해줘"                          # 단계별 로그와 함께 실행
scripts/install_daily.sh                                              # 매일 08:31 실행 등록 (해제: scripts/uninstall_daily.sh)
```

`agent.py`는 에이전트 루프를 SDK 없이 직접 구현했습니다(약 200줄). 안전장치는 다음과 같습니다.

- 허용한 도구만 씁니다. 혼자 도는 모드에서는 내 조건을 수정하는 도구를 쓰지 않습니다.
- 최대 25단계까지만 돌고, 토큰 예산을 넘으면 멈춥니다.

## MCP 도구

| 도구 | 하는 일 | 부작용 |
|---|---|---|
| `list_boards` | 지금 보고 있는 공고 유형과 설정 가능한 값 | 없음 |
| `recent_notices` | 최근 모집공고와 접수 상태. 마감 공고는 PDF를 읽지 않음 | 없음 |
| `check_new_notices` | 아직 처리하지 않은 새 모집공고 | 본 글 기록 |
| `find_notices` | 공고를 이름으로 찾기 ("고덕강일", "51차") | 없음 |
| `get_notice` / `extract_schedule` | 게시글 본문·첨부 목록 / 본문에서 뽑은 일정 후보 | 없음 |
| `read_notice_pdf` | 모집공고문 PDF만 골라 목차와 핵심 섹션을 반환하고, 청약 전략에 영향을 주는 특이 규칙도 함께 반환 | PDF 캐시 |
| `get_housing_costs` | 서버가 파싱·계산한 비용표. 분양은 대출·필요 현금·취득세·월 부담(만기 30·40년 × 금리), 장기전세는 전세대출과 가용 현금으로 가능한 세대 | 없음 |
| `get_my_profile` / `check_profile_gaps` | 내 조건과 계산값(나이·신혼 기간 등) / 이 공고가 묻는데 비어 있는 항목 | 없음 |
| `update_my_profile` | 조건 수정. 확인 창에서 체크한 항목만 저장 | 프로필 쓰기 |
| `propose_registration` → `confirm_registration` | 일정 플랜 생성(원문 근거 확인) → 사람 확인 후 등록 | **캘린더 쓰기** |
| `record_application` | "접수했어"면 발표 일정, "당첨됐어"면 서류·계약 일정 플랜 | 진행 단계 기록 |
| `save_receipt_numbers` | "접수했어" 때 받은 접수번호 저장 (본인·배우자 구분) | 로컬 DB 기록 |
| `check_my_results` | 당첨자 발표 글의 당첨자·예비입주자 명단 PDF에서 내 접수번호를 찾아 당첨 / 예비 n번 / 명단에 없음 판정 | 결과 기록 |
| `my_receipts` | 저장된 접수번호와 마지막 조회 결과 | 없음 |
| `mark_notice_processed`, `recent_calendar_events` | 처리 완료 표시, 등록 내역 | 상태 기록 |

프롬프트 `summarize_notice`와 `process_new_notices`는 요약을 항상 같은 형식으로 만들게 합니다. 형식은 `src/sh_notice_mcp/prompts.py`에 있습니다.

## 안전하게 만든 부분

- **캘린더에 쓰는 길은 하나뿐입니다.** `confirm_registration`이 macOS 기본 선택 창을 직접 띄우고, 사람이 체크한 일정만 씁니다. AI가 대신 누를 수 없고, 확인할 수단이 없으면 등록하지 않습니다.
- **날짜는 원문으로 검증합니다.** 모든 일정은 게시글 본문이나 공고문 PDF의 근거 문장과 쪽 번호가 있어야 등록됩니다. AI가 날짜를 잘못 읽으면 거부합니다.
- **숫자는 서버가 계산합니다.** 분양가 평균, 대출, 취득세, 보증금 전환은 코드로 계산합니다. 계산식은 공고문 예시표를 원 단위까지 재현하는지 테스트합니다.
- **개인정보는 로컬에만 둡니다.** 프로필, DB, PDF 캐시는 `~/.sh-notice-mcp/`에만 저장되고, API 키는 macOS 키체인에만 둡니다.

휴대폰에서 맥 없이 쓰고 싶다면 [docs/REMOTE.md](docs/REMOTE.md)의 원격 서버(개인정보 저장 없음)를 띄워 claude.ai 커넥터로 연결하세요.

설계 이유, 사이트 분석 결과, 테스트로 잡은 버그는 [docs/DESIGN.md](docs/DESIGN.md)에 정리했습니다.

## 대출·세금 기준

공고문에 대출 조건이 있으면 그 값을 씁니다. 없으면 **일반 기준(추정)** 을 쓰고, 요약에도 그렇게 표시합니다.

- 분양 주택담보대출: 서울 규제지역 LTV 40%, 생애최초는 70%
- 전세대출: 버팀목 신혼·일반 상품 또는 시중은행 상품
- 취득세: 1주택 세율과 생애최초 감면

이 숫자들은 2026년 10월 기준입니다. 정책이 바뀌면 `src/sh_notice_mcp/loans.py`와 `taxes.py` 맨 위의 상수만 고치면 됩니다. 대출 금리는 프로필에 `loan.expected_rate_pct`를 적으면 그 값을 쓰고, 공고에 나온 금리 범위도 함께 보여 줍니다.

## 다른 환경

| 변수 | 기본값 | 설명 |
|---|---|---|
| `SH_NOTICE_CONFIRM` | macOS `dialog`, 그 외 `elicit` | 최종 확인 방식 |
| `SH_NOTICE_BACKEND` | macOS `mac`, 그 외 `ics` | 캘린더 (맥 캘린더 / `.ics` 파일) |
| `SH_NOTICE_CALENDAR` | `SH 공고` | 일정을 넣을 캘린더 이름 |
| `SH_NOTICE_DATA_DIR` | `~/.sh-notice-mcp` | 프로필·DB·PDF 캐시 위치 |
| `SH_AGENT_MODEL` | `claude-sonnet-5-5` | 에이전트가 쓰는 모델 |

MCP elicitation은 사양상 클라이언트가 자동으로 응답할 수 있습니다. 그래서 macOS 확인 창보다 보장 수준이 낮습니다.

## 알려진 한계

- 자격 판단은 참고용입니다. 소득·자산 기준은 예외가 많아서 최종 확인은 원문으로 해야 합니다.
- 스캔(이미지)본 PDF와 HWP 첨부는 읽지 못합니다. 읽지 못하면 그렇다고 알려 줍니다.
- 게시판 1페이지만 확인합니다. 사이트 구조가 바뀌면 파서가 명확한 오류를 냅니다.
- 비용표 자동 계산은 분양·장기전세 공고문 형식만 지원합니다.
